Mos of the time you want to use slices instead of arrays
- though in the sense of allocating a chunk of memory for the rat program you definitely want to use arrays, so the contents stays in one place on memory instead of rolling away whenever

What makes slices superior to arrays?
- length is not part of the type for a slice
- we can write functions that process slices of any size, and we can grow them as needed

Working with slices are subtle compared to arrays
- we dont specify the size of the slice when declaring

```go
// this makes a slice, notice there is no length specified
var x = []int{10, 20, 30}
```

 Just like arrays, we can also specify only the indices with values in the slice literal:
 ```go
 var x = []int{1, 5: 4, 6, 10: 100, 15}
 ```

## nil

Since no value is assigned, x is assigned the zero value for
a slice, which is something we haven’t seen before: nil
- its different from null (compared to javascript)
- nil is identifier that represent the lack of value for some type
- nil has no type, it can be compared to against other values


Slice is a type that is not comparable!
- we can though compare slice with at nil value(to check whether its empty)

## len
works just like on the arrays
- in case the slice is empty/nil it returns 0, duh

## capacity
Every slice has a capacity, which is the consecutive memory locations reserved for it.
- each time you append to a slice one or more values is added to the end of slice
- when length reaches the capacity, the append function or the runtime in go allocates new slice with larger capacity. 
- the golang runtime doubles the capacity whene capacity is lower than 1024 and after that it expands 25% every time when reallocating.
