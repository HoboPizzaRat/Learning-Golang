Go allows you to pass a string to the built-in len function to find the length of the
string. Given that string index and slice expressions count positions in bytes, it’s not
surprising that the length returned is the length in bytes, not in code points:

The following prints out 10, not seven
```go
var s string = "Hello (insert emoji here)"
fmt.Println(len(s))
```

Because of this complicated relationship between runes, strings, and bytes, Go has
some interesting type conversions between these types

A common bug for new Go developers is to try to make an int into
a string by using a type conversion
```go
var x int = 65
var y = string(x)
fmt.Println(y)
```
- the above prints the value "A" not 65
- go 1.15 and later blocks type conversion to string from any integer other than rune or byte

A string can be converted back and forth to a slice of bytes or a slice of runes. 

example of converting string to slices
```go
var s string = "Hello, "
var bs []byte = []byte(s)
var rs []rune = []rune(s)

fmt.Println(bs)
fmt.Println(rs)

// outputs:
// [72 101 108 108 111 44 32 240 159 140 158]
// [72 101 108 108 111 44 32 127774]

```

Most data in Go is read and written as a sequence of bytes, so the most common
string type conversions are back and forth with a slice of bytes.
